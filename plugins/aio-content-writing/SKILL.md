# Контент, который цитируют AI-поисковики

## Зачем этот скилл

AI-поисковики (Google AI Overview, ChatGPT Search, Perplexity, Yandex Нейро) работают принципиально иначе, чем классический Google. По данным Ahrefs за февраль 2026, AI Overview забирает около 58% кликов у первой позиции выдачи. Сайт может быть в топ-1 и терять больше половины трафика, потому что AI вырезает фрагмент с другой страницы.

Этот скилл — рабочая структура для написания и переписывания текста так, чтобы LLM **вырезали и цитировали именно ваши абзацы**.

## Ключевая модель: как AI читает страницу

Классический Google: оценивает страницу целиком → одна страница, одна позиция.

AI-поисковики: разрезают страницу на фрагменты-чанки (**300–500 символов**, обычно 1–3 абзаца под одним подзаголовком) и ищут **лучший фрагмент**, а не лучшую страницу.

Механика индексации:
1. Перед поиском AI разбивает промт пользователя на веер из 10–15 подзапросов (**Query Fanout**): из «посоветуй клинику на Петроградке, где перелечат каналы под микроскопом во сне» получаются маски «эндодонтия микроскоп СПб», «лечение зубов в седации цены», «стоматология Петроградский район рейтинг» и т.д.
2. Каждый фрагмент при индексации получает «смысловой отпечаток» (эмбеддинг).
3. Подзапросы превращаются в такие же отпечатки.
4. Система находит 20–50 кандидатов по близости отпечатков.
5. Второй фильтр (re-ranker) пересчитывает каждого кандидата вместе с вопросом и оставляет 3–5 (иногда до 7) лучших.
6. Эти фрагменты AI вставляет в ответ и на них ставит ссылку. В рекомендательных списках обычно называется не более 5 брендов.

**Два главных вывода:**
- Статья на 5 000 слов с одним сильным абзацем = 1 шанс на цитирование. Статья из 5 сильных абзацев = 5 шансов. **Решает не длина, а количество сильных самостоятельных фрагментов.**
- Страница должна закрывать **весь веер подзапросов**, а не один ключ. Если раскрыта цена, но нет ни слова про технологию и условия — AI возьмёт конкурента, у которого раскрыты все смежные микро-интенты. Один интент = один чанк: цену, этапы, сроки и кейсы не смешивать в одном абзаце.

## Принцип 1. Формула Answer Unit (структура абзаца)

Каждый абзац, который должен цитироваться, строится из 4 элементов в строгом порядке:

### 1. Claim (тезис) — ВСЕГДА первое предложение

Одно предложение, которое прямо отвечает на вопрос пользователя. Принцип BLUF (Bottom Line Up Front): главное вперёд, детали потом.

**Почему первым:** AI смотрит на начало фрагмента. Если ответ спрятан в третьем предложении, AI пропустит весь абзац, даже если ответ идеальный.

### 2. Context (рамка)

Уточнение: для кого, когда, при каких условиях.

**Не работает:** «Витамин D снижает риск переломов на 20%» — для кого? для всех?
**Работает:** «...для женщин старше 60 при дозировке 800 МЕ»

### 3. Proof (доказательство)

Цифра, исследование, кейс, источник. Конкретика, а не «по нашим исследованиям».

**Не работает:** «По данным наших исследований»
**Работает:** «Ahrefs, февраль 2026, выборка 300 000 ключевых слов»

Фрагмент с конкретикой всегда побеждает фрагмент без конкретики.

**Оценочные прилагательные AI игнорирует полностью** — в них нет извлекаемого факта. Каждую оценку переводи в проверяемое утверждение:

| Оценка (мимо) | Факт (цитируется) |
|---|---|
| Работаем быстро | Изготавливаем заказ за 7 рабочих дней |
| Большой опыт | Работаем с 2014 года, 340 реализованных проектов |
| Высокое качество | Производим 200 тонн металлоконструкций в год по ГОСТ 23118-2019 |
| Доступные цены | От 3 200 ₽ за м², без наценки за срочность до 3 дней |

### 4. Takeaway (вывод/действие)

Что читателю делать с этой информацией. Конкретное действие.

### Пример применения формулы

**Запрос:** «дозировка витамина D»

**Не работает (типичный SEO-текст):**
> В последнее время всё больше людей интересуется здоровьем. Витамин D играет важную роль, он необходим для костей. Дозировка 600–800 МЕ в день.

Три предложения воды, факт только в четвёртом. AI пройдёт мимо.

**Работает (по Answer Unit):**
> Рекомендуемая дозировка витамина D для взрослых — 600–800 МЕ в день (рекомендация Национального института здоровья США для людей 19–70 лет без дефицита). При выявленном дефиците эндокринологи назначают 2 500–5 000 МЕ курсом 8–12 недель. Перед приёмом высоких доз сдайте анализ 25(OH)D.

- Claim: «600–800 МЕ в день» — в первом предложении.
- Context: «для взрослых 19–70 лет без дефицита».
- Proof: «рекомендация Национального института здоровья США».
- Takeaway: «сдайте анализ 25(OH)D перед высокими дозами».

## Принцип 2. Структура страницы: Entity → Property → Value

LLM хранят знания в виде троек: **сущность → свойство → значение**.

Пример: «Tesla Model 3 разгоняется до 100 км/ч за 3,1 секунды»
- Сущность: Tesla Model 3
- Свойство: разгон до 100 км/ч
- Значение: 3,1 секунды

Когда пользователь спрашивает «какой разгон у Tesla Model 3», модель ищет именно такую тройку.

Этот принцип ложится прямо на структуру HTML-страницы:

| Элемент | Содержание |
|---|---|
| `<h1>` | Сущность (о чём страница целиком) |
| `<h2>` | Конкретное свойство сущности |
| Абзац под `<h2>` | Значение этого свойства |

### Критическое правило для H2

Каждый H2 — это **конкретное свойство**, а не размытая рубрика.

**Не работает:** «Основные особенности», «Почему стоит выбрать нас», «Преимущества»

**Работает:** «Время разгона Tesla Model 3», «Дозировка витамина D для взрослых», «Стоимость внедрения CRM в малом бизнесе»

Система не понимает, что стоит за размытыми заголовками. За конкретным свойством — понимает.

## Принцип 3. Называйте сущности по имени в каждом абзаце

AI вырезает фрагмент **без окружающего контекста страницы**. Если в абзаце написано «он позволяет автоматизировать», AI не понимает, кто такой «он». Фрагмент бессмысленный — система его не возьмёт.

**Не работает:** «Стоит отметить, что **у него** есть преимущество перед конкурентами»

**Работает:** «Робот-пылесос **Roborock S8 MaxV Ultra** строит 3D-карту помещений двумя камерами и лидаром»

Запрещённые местоимения и отсылки в самостоятельных абзацах:
- «он», «она», «оно», «они»
- «этот сервис», «данный продукт», «наша платформа»
- «как мы говорили выше», «в предыдущем разделе»

### Тест на самостоятельность

Покажите абзац коллеге **без остальной статьи**. Если он понимает суть — фрагмент работает. Если спрашивает «а это про что?» — переписывайте.

## Принцип 4. Information Gain (уникальная информация)

Если у конкурента всё то же самое — у AI нет причины цитировать именно вас. Возьмёт Википедию.

**Одна статья на 1 000 слов с тремя уникальными фактами ценнее статьи на 5 000 слов, где всё можно найти у конкурентов.**

### Пять типов уникальной информации (от самого сильного к самому слабому)

1. **Собственные данные** — ваши исследования, внутренние метрики, A/B-тесты.
2. **Уникальные кейсы и опыт** — «мы попробовали это, получилось вот так».
3. **Свежие данные** — у конкурентов ссылки за 2023, у вас за 2026.
4. **Новый угол на знакомую тему** — «почему 80% советов по SEO не работают».
5. **Оригинальная методология** — ваш фреймворк или классификация, которой нет нигде.

### Практическая проверка

1. Загуглите ваш целевой запрос.
2. Откройте топ-3 результатов.
3. Выпишите все факты из них.
4. Посмотрите свою страницу: есть ли минимум 3 факта, которых нет ни у кого из топ-3?

Если нет — у AI нет причины цитировать именно вас.

## Принцип 5. Answer First на уровне страницы

Правило первого предложения работает и в масштабе всего документа:

- **Первые 30% текста** — самый плотный контент. Модели часто не индексируют дальше **первых ~1500 слов**: всё «припасённое на потом» просто не будет прочитано.
- **Блок «Коротко» (TL;DR) в начале** — 3–5 тезисов с главными цифрами и выводами. Человеку — быстрый ответ, машине — концентрат смысла на входе.
- Драматургия «сначала контекст, потом раскрытие» — фатальна: AI вырежет первый абзац с водой и решит, что страница нерелевантна. Если «разогрев» нужен читателю, ставь его **после** блока с прямым ответом.

## Принцип 6. Форматы-магниты для цитирования

Материалы с таблицами и списками цитируются примерно **на 40% чаще**. Приоритет форматов:

1. **Сравнительная таблица** — AI выводит такие таблицы в ответ целиком. В финальной вёрстке это должен быть настоящий `<table>` с поясняющим `<caption>` (не `<div>` и не картинка) — если пишешь markdown, обычная таблица подойдёт.
2. **Нумерованные шаги** — этапы, инструкции, «как выбрать».
3. **Маркированные списки** — состав услуги, критерии, ошибки. Каждый пункт самодостаточен: с именем сущности и по возможности с цифрой.
4. **Определение** — «X — это …» одним абзацем на 40–60 слов.
5. **FAQ-блок** — прямая заготовка для нейроответа.

### Правила FAQ

- Ответ — **2–4 предложения (40–60 слов)**, прямой тезис с первого предложения, имя сущности, цифра.
- **Вопрос в ответе дословно не повторять** — ответ должен быть самодостаточным и без него.
- Вопросы брать из реальных формулировок: подсказки поиска, «Люди также спрашивают», вопросы клиентов менеджерам, FAQ конкурентов из топа.
- Если на странице будет разметка `FAQPage` — текст в разметке обязан **посимвольно совпадать** с видимым текстом (иначе это считается манипуляцией).

## Принцип 7. Свежесть и автор

- **Даты прямо в тексте**: «по состоянию на август 2026», год у каждой статистики. Свежие данные — сильный фактор выбора источника; по одному из исследований, контент, обновлённый за последние 30 дней, используется моделями в ~3 раза чаще.
- При обновлении статьи реально **обновляй цифры и примеры**, а не только дату.
- **Блок автора** с именем, должностью и стажем — анонимный текст AI старается игнорировать. Если в задаче есть кому подписать текст — подписывай.

## Границы скилла: что текст решает, а что нет

Идеальный текст выигрывает **отбор фрагментов**, но в пул кандидатов страница попадает из обычной поисковой выдачи. Три ограничения, о которых стоит предупредить пользователя, если его цель — «попасть в ответы ИИ»:

1. **Позиции.** Вероятность цитирования максимальна у страниц в ТОП-1–3 и обрывается почти до нуля после ТОП-10. Яндекс Алиса берёт источники строго из ТОП-20 Яндекса. Текст на странице с 15-й позицией не процитируют, каким бы он ни был.
2. **Техдоступность.** Контент должен быть в HTML: боты нейросетей не исполняют JavaScript и **не читают текст на картинках** (скриншоты отзывов для AI не существуют — только текстом).
3. **Внешний консенсус.** AI доверяет фактам, подтверждённым независимыми источниками. Это за пределами текста одной страницы.

Эти три пункта — не работа данного скилла, но честная рамка ожиданий.

## Чек-лист перед публикацией абзаца

Прогоняй каждый ключевой абзац по списку. Если хотя бы один ответ «нет» — переписывай.

1. Тезис стоит в **первом предложении** (BLUF)?
2. Сущность **названа по имени** (без «он», «этот», «данный»)?
3. Есть **конкретная цифра, источник или дата** (не «по данным исследований», а конкретно)?
4. Есть **takeaway** — что делать читателю?
5. Абзац **понятен без остального текста страницы**?
6. Объём абзаца **в районе 300–500 символов** и в нём **один интент** (не смешаны цена, сроки и этапы)?
7. Заголовок раздела (H2) — это **конкретное свойство**, а не «преимущества»/«особенности»?
8. Оценочные прилагательные («быстро», «качественно») **заменены фактами с цифрами**?
9. На странице есть **минимум 3 уникальных факта**, которых нет в топ-3 выдачи?

И по странице целиком:

10. Главное — в **первых 30% текста**, есть блок «Коротко»?
11. Страница закрывает **весь веер подзапросов** (Query Fanout), а не один ключ?
12. Есть хотя бы **одна таблица или список** там, где это уместно, и **FAQ** с ответами по 40–60 слов?

## Полный рабочий пример: до и после

### Исходник (типичный SEO-текст)

> Автоматизация бизнес-процессов становится актуальной задачей. Многие компании ищут способы повысить эффективность. Одним из решений являются специализированные платформы. Они позволяют сократить время на рутинные операции.

**Проверка:**
- Тезис в первом предложении? Нет (общая фраза «становится актуальной»).
- Сущность названа? Нет («специализированные платформы», «они»).
- Цифра/источник? Нет.
- Уникальная информация? Нет (есть на десятках тысяч сайтов).

Не пройдено ни одного критерия.

### Переписано по Answer Unit

> Платформа **Zapier** сокращает рутинные операции в среднем на **4 часа в неделю** на сотрудника (исследование Zapier, 2025). Основное применение — связка CRM, почты и таск-трекера: заявка с сайта автоматически попадает в CRM, создаёт задачу в Asana и отправляет письмо клиенту. Перед запуском **тестируйте каждый сценарий на 10 реальных записях** — ошибка в одном звене ломает всю логику.

**Проверка:**
- Claim с цифрой первым: да («сокращает на 4 часа в неделю»).
- Сущность названа: да (Zapier).
- Источник и год: да (исследование Zapier, 2025).
- Takeaway: да («тестируйте на 10 реальных записях»).
- Самостоятельность: да (понятно без остальной страницы).

AI может вырезать этот фрагмент и вставить в ответ на запрос «автоматизация бизнес-процессов» / «Zapier для малого бизнеса» / «как внедрить Zapier».

## Рабочий процесс при написании текста по этому скиллу

Когда пользователь просит написать или переписать текст:

1. **Уточни целевой запрос(ы) и разложи в веер.** Возьми 1–3 реальных разговорных промта (как клиент спросил бы у ChatGPT) и разбей каждый на 10–15 подзапросов — так же, как это делает сам AI (Query Fanout). Быстрый способ собрать полный веер — перемножить продукт на 12 типовых фреймов запросов: *поиск и подбор, сравнение «X или Y», инструкция, репутация и отзывы, экспертиза «как работает», локация «где рядом», цена «сколько стоит под ключ», аналитика рынка, критика «какие недостатки», синтез «составь список», прогноз, верификация «правда ли, что»*. Без веера формула работает на один ключ вместо всего интента.
2. **Распиши структуру страницы как тройки.** H1 = сущность, каждый H2 = конкретное свойство (лучше — в форме вопроса из веера). Каждый непокрытый подзапрос из шага 1 → свой H2-блок. Если получился H2 типа «Преимущества» — это сигнал переформулировать в свойство.
3. **Спланируй форматы.** Где сравнение — таблица, где этапы — нумерованный список, в конце — FAQ на 3–7 вопросов. Блок «Коротко» — в начало.
4. **Пиши каждый абзац по Answer Unit.** Claim → Context → Proof → Takeaway. Тезис всегда первым предложением, объём чанка 300–500 символов, один интент на абзац.
5. **Называй сущность по имени в каждом ключевом абзаце.** Никаких «он», «этот сервис». Оценочные прилагательные заменяй фактами с цифрами.
6. **Добавь Information Gain и свежесть.** Минимум 3 факта, которых нет в топ-3 выдачи; актуальные даты прямо в тексте.
7. **Прогон по чек-листу.** Каждый абзац и страница целиком — по 12 пунктам выше.

При переписывании существующего текста — то же самое, плюс сначала покажи пользователю, какие критерии не пройдены в исходнике (как в примере выше), чтобы он видел логику изменений.

## Важно про оформление финального текста

Маркеры «Не работает» / «Работает», списки проверок и разборы по критериям — это **внутренний рабочий формат скилла** для разбора и обучения. В **финальный текст для сайта, статьи или лендинга** их не вставляй. Финальный текст — это чистая проза по формуле Answer Unit, без декоративных маркеров, без чек-листов внутри самого контента, без «плохой пример / хороший пример». Разбор по критериям показывай только когда пользователь явно просит объяснить, почему текст переписан именно так.

## Семь принципов в одном экране (для ссылки)

1. **Самостоятельный чанк 300–500 символов.** Каждый абзац работает без контекста страницы, один интент на абзац.
2. **Формула Answer Unit.** Claim → Context → Proof → Takeaway. Тезис первым.
3. **Структура Entity → Property → Value.** H1 = сущность, H2 = свойство (вопрос из веера подзапросов), абзац = значение.
4. **Имя сущности в каждом абзаце.** Никаких «он», «этот», «данный». Факты с цифрами вместо оценок.
5. **Information Gain.** Минимум 3 факта, которых нет в топ-3 выдачи.
6. **Answer First на уровне страницы.** Главное — в первых 30% и до 1500 слов, блок «Коротко» в начале.
7. **Форматы-магниты.** Таблицы, списки, FAQ по 40–60 слов — на ~40% выше цитируемость.
