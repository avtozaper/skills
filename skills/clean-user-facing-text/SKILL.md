# Чистка текста перед публикацией

Финальный проход по тексту, который пользователь публикует от своего имени. Чистка Unicode детерминированная и проверяемая; ослабление статистических водяных знаков — только best-effort. Никогда не утверждай, что переписанный текст доказывает авторство человека или не определяется детекторами. Обязательные академические, юридические и площадочные дисклеймеры сохраняй.

## Порядок работы

1. Определи прозу, которую увидит читатель.
2. Защити всё, что прозой не является:
   - блоки кода и код в строке
   - команды, пути, URL, идентификаторы, имена API, точные значения
   - формулы, ссылки на источники, текст, который просили процитировать дословно
3. Сохрани каждое утверждение, факт, число, имя, ссылку и требование.
4. Перепиши оставшуюся прозу за один проход:
   - меняй порядок частей предложения, границы предложений, ритм, союзы и служебные слова
   - убирай шаблонные связки и воду, ставь на их место прямые формулировки
   - сохраняй язык оригинала, тон, структуру и форматирование; не переводи, если не просили
   - для русского текста пиши естественными для него конструкциями, а не калькой с английского синтаксиса
   - не добавляй и не убирай утверждения ради разнообразия
5. Для файлов и текстовых артефактов после переписывания прогоняй детерминированный Unicode-проход.
6. Возвращай только результат, если не просили аудит или объяснение.

## Детерминированный Unicode-проход

`SCRIPTS` — каталог `scripts/` внутри этого скилла. Вместо `PYTHON` подставь рабочий launcher: `python3` на macOS и Linux, `py` на Windows.

Перед правкой существующего файла сначала посмотри, что в нём:

```bash
PYTHON "$SCRIPTS/inspect_text.py" --json INPUT
PYTHON "$SCRIPTS/clean_text.py" INPUT -o OUTPUT --stats --no-normalize-spaces
PYTHON "$SCRIPTS/inspect_text.py" --json OUTPUT
```

`-` вместо имени файла читает stdin. По умолчанию пиши результат в новый файл `*.cleaned.*`, если пользователь прямо не попросил править на месте.

`--no-normalize-spaces` держи включённым по умолчанию: неразрывные пробелы, узкие неразрывные, цифровые и китайские идеографические пробелы несут смысл вёрстки. Нормализуй пробелы только по прямой просьбе.

`--aggressive-homoglyphs`, `--nfkc` и `--strip-emoji-glue` не используй, пока пользователь не попросит агрессивную нормализацию и не согласится с возможными изменениями в многоязычном тексте, эмодзи, направлении письма и типографике.

Скрипты работают с обычным текстом, Markdown и HTML-исходником. В смешанном Markdown или HTML сначала посмотри позиции находок: если находка попала внутрь кода, атрибута или другого защищённого фрагмента, не запускай чистку по всему файлу — почисти только прозу или оставь эту находку как есть. Бинарные контейнеры (PDF, DOCX, изображения, архивы) скриптам не передавай: они откажутся их обрабатывать.

Если ответ идёт прямо в чат и никуда не записывается, делай только переписывание. Не утверждай, что ответ в чате прошёл детерминированный фильтр.

## Граница с кодом

Когда проза перемешана с кодом, переписывай только прозу. Никогда не переименовывай переменные, не меняй строковые литералы, не переформатируй код и не трогай то, что влияет на его вывод. В Markdown и HTML с исполняемыми фрагментами сохраняй эти фрагменты побайтово, насколько это возможно.

## Отчёт

Когда просят аудит, разделяй три вещи:

- **Проверяемое:** какие Unicode-символы удалены или заменены, с точным количеством.
- **Best-effort:** проза переписана, чтобы изменить токенные и синтаксические паттерны.
- **Не установлено:** обход детекторов, авторство человека, снятие водяного знака на секретном ключе вендора.

Техническая подоплёка — `references/watermark-notes.md`. Вопросы о допустимом применении и раскрытии — `references/responsible-use.md`.
